What it does

Agent Floor runs Claude Code, Codex and Grok agents as command-line sessions inside one desktop app, and I can reach them from my phone through messaging channels. An agent can also be given its own Docker Linux desktop to work in.

It is the main thing I build. The code is private, and it has no outside users yet.

How it fits together

Decisions

  • Real command-line tools. Each agent is a real command-line tool (claude, codex, grok) that the app starts and manages.
  • An approval gate for risky actions. I added an approval card with trust levels. Enforcement was still off by default at the 12 October review, which the limits below explain.
  • Tests and a way back. The app has over 1,300 automated tests, and every release ships with a rollback.

What broke

After I switched an agent from Grok to Claude Opus, the picker showed the new model, but the agent's persona file and status card still named the old engine. Claude Code had also frozen the system prompt from the first message of that session and was replaying it on every resume.

The fix: every turn now carries a "who is speaking" card built from the live roster, Claude Code starts with the system prompt snapshot turned off, and the personas no longer name an engine. It went into a Linux lab build, not a public release.

Limits

I ran a multi-agent architecture review of the runtime. It showed that the agents were not yet sandboxed: they ran as my own user, and gate enforcement was off by default. A command-line tool running as the same user is not a sandbox.

The review recommended a thin policy layer instead of another agent framework: an authorise check that answers allow, deny or requires approval and fails closed, plus an emergency stop the interface cannot clear. That is at the design stage. Nothing from it is built yet.

This page describes the app as my own review found it on 12 October 2026.
